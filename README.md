# Custom MCP Node.js Project

A runnable **full-stack monorepo** generated by the **AI Project Builder**
from reusable modules in the base repository (`sjinnovation/base`).

Layout: `client/` (Next.js App Router) + `server/` (Node.js API) + `supabase/` at repo root.

## Getting started

```bash
npm install
cp .env.example .env.local   # fill in the values below
npm run dev                  # Next.js on http://localhost:3000
npm run dev:server           # API on http://localhost:4000 (separate terminal)
```

## Supabase

- Apply the SQL migrations under `supabase/migrations/` to your Supabase project.
- Deno edge functions (if any) live under `supabase/functions/` and deploy separately.

## Manual follow-ups

- Client expects a Supabase client at client/lib/supabaseClient.ts that exports a configured `supabase` instance (uses the anon key on the client). This file is not provided by the module and must be added to the app.
- Supabase migrations/functions (supabase/) are copied by the pipeline only; run your migrations (e.g. `supabase migration up`) to create the `example` table described in the module documentation.
- Module name in server code has been changed from 'example-module' to 'example' to follow the feature namespace and avoid catalog-id folder names.
- Ensure Tailwind and Next.js App Router are configured in the client/ workspace. This module adds files under client/, but does not include global scaffolding (tsconfig, next.config, tailwind.config).
- No `modules/` directories or `example-module` folder segments are present in the output. Adjust import aliases if your monorepo uses a different `@/` mapping.
- Monorepo layout: run `npm install` at repo root, then `npm run dev` for client and `npm run dev:server` for API.
- Set API_BASE_URL in .env.local (e.g. http://localhost:4000) so the client can reach the server.

See `PROJECT-MANIFEST.json` for the full machine-readable selection.
